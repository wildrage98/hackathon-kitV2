# rule-check

## 순서
1. README 의 규칙 문장을 전부 뽑아 표로: `규칙 | 입력에서 어떻게 확인 | 경계(같을 때 허용?) | 코드명`.
   경계가 애매하면("20분 전까지" = 같은 시각 허용?) 사용자에게 담당자 확인을 요청하고, 답이 오기 전까지는 포함(≤)으로 두고 DECISIONS 에 적는다.
2. `engine.verify(result, tables)` 를 먼저 쓴다 — 규칙마다 `Violations.add(code, message, 위치)`. 생성 함수의 변수나 중간값을 쓰지 말고 **결과 JSON + 입력 테이블만** 본다.
3. 검증기 자체 검증: `kitlib.verify.mutate_check(verify_fn, 정상결과, [("정원 초과", 정원을 1로), ("기한 위반", 시각을 늦춤), ("휴무자 배정", OFF 사람 추가), ("근무자 누락", 한 명 제거)])` → 전부 잡혀야 한다. tests/ 에 고정.
4. 생성 코드를 짠 뒤 매 기능마다 `verify` 결과를 보고한다. 위반이 있으면 **생성 코드를 고친다**(검증기를 느슨하게 하지 않는다). 둘 중 어느 쪽이 맞는지 모르면 사용자에게 묻는다.
5. 내보내기 JSON 이 있으면 CLI(`tools/verify_output.py`)로 파일 기준으로 한 번 더.

## 경계값 목록 (요구 문장에 따라 고른다)
정원과 같을 때 / 기한·시각과 같을 때 / 자정을 넘는 근무·일정의 기준일 / 휴무·제외 대상 / 한 지점 수요 > 정원 / 비대칭 소요시간 / 빈 입력·기간 밖 날짜 / 같은 키 중복 / 참조 없는 ID

## 보고 형식
`검사 N건, 위반 M건 (코드별 수) — 로그: logs/...` 한 줄 + 위반 상위 5개. "통과"는 로그 파일이 있을 때만.
