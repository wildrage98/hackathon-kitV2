# 09 — 확인 문제 답안 초안 (제출 15분 전, docs/QUIZ.md)

먼저 터미널에서: `python3 tools/quiz_prep.py --project <이름>` (재료 수집 → docs/QUIZ_CARD.md, 빈 훅 목록).
그 다음 에이전트에 타이핑 한 줄:
```
hackathon-kit/prompts/09-quiz.md 를 읽고 수행해.
```

```
너는 이 제출물을 읽고 "제출 후 이해도 확인" 질문(6문항 × 5분, 복사 불가)을 내는 평가자이면서, 그 답을 준비하는 조수다. 코드는 고치지 마라.

1. 읽어라: HOW_TO_RUN.md, AI_COLLABORATION.md, docs/DECISIONS.md, docs/VERIFICATION.md, docs/QUIZ_CARD.md(있으면), tests/*.py 의 테스트 이름과 docstring, logs/ 최근 파일 3개, app/*.py 머리말.
2. 아래 6유형마다 질문 1개를 만들어라. 평가자가 그렇게 내듯 **내 문서의 문장을 그대로 인용**하는 형태로.
   ① 구조 선택 — 왜 그 구조인지, 고려했을 대안(동기/비동기, 메모리/DB, 단일/다중 등), 감수한 제약
   ② 입력 → 화면 흐름 — 적용·선정·생성·독립 검증·저장이 각각 어떤 모듈의 책임이고 상태는 어디에 보관되나
   ③ 검증함 / 가정함 / 미구현 구분 + 다른 평가자가 볼 파일·테스트·로그
   ④ 실패 경로 — 잘못된 입력 적용 / 적용 후 미재생성 / 실행 중 재요청 — 정상 경로와 비교
   ⑤ 조건 변경(정원·여유·휴무 등) → 결과·생성 시간 예측, 알고리즘의 병목·위험, AI 설명 없이 확인하는 방법
   ⑥ AI 산출물 중 받아들인 것 / 고치게 한 것 / 버린 것과 판단 근거(테스트·명령 결과·제약·바뀐 코드) — AI_COLLABORATION 의 정책 이름을 인용
3. 각 질문에 답을 500자 안팎으로 써라. 틀: 결론 1문장 → 근거(파일 경로·테스트명·숫자) → 대안과 버린 이유 → 제약/한계.
   저장소에 없는 사실은 쓰지 마라. 근거(파일·테스트·로그·숫자)를 못 찾은 주장은 그 자리에 `[근거 없음 — 문서 또는 테스트 보강 필요]` 라고 표시해라.
4. 문서에 남은 `(채움` 과 비어 있는 굵은 소제목(구조 선택 / 모듈과 상태 / 잘못된 입력·어긋난 순서 / 설계 기준 / 조건을 바꾸면 / 검증함·가정함·미구현)을 목록으로 보고해라.
5. docs/QUIZ.md 를 덮어써라 (양식은 그 파일 그대로). 맨 아래 "암기 카드": 파일 5 · 테스트 5 · 숫자 5 · 명령 3 · 한계 3.

출력: docs/QUIZ.md 경로 + [근거 없음] 목록 + 빈 훅 목록. 그 외 설명 생략.
```

받은 뒤 내가 할 일: [근거 없음] 은 문서를 고치거나 답에서 뺀다 → 답 6개를 소리 내어 한 번, 눈으로 한 번 → 암기 카드만 다시 본다.
