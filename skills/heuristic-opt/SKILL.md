# heuristic-opt

## 원칙
- 정확해(최적해)를 찾지 않는다. **규칙 준수 → 기준 우선순위 → 지표로 비교**.
- 첫 버전은 30분 안에 "규칙만 지키는 가장 단순한 답"(예: 수요 많은 순 greedy). 그 다음 기준을 하나씩 넣는다.
- 기준 숫자(한도·배수·최소 인원)는 전부 PARAMS. 코드 상수 금지. 문서에 "담당자 확인값 / 개발자 가정" 구분.

## 순서
1. 기준을 **우선순위 목록**으로 적는다 (예: 규칙 > 접근성(한도 2단계) > 우회 한도 > 자원 수 > 총 시간). `docs/DECISIONS.md` 에 먼저.
2. 빌딩블록: 지점→후보 배정 `kitlib.vrp.cover_assign`, 정원 묶음·순서 `make_routes` + `two_opt`, 시간표 `timetable`, 거리·보행 `kitlib.geo`, 디스패칭 `kitlib.schedule`.
3. 결과 지표를 반드시 같이 계산: 자원 수(버스·장비), 적재율/가동률, 평균·최대 시간, 한도 초과 수, 기준 등급별 인원. `view()` 의 metrics 로 노출.
4. **현실성 점검** (사용자에게 숫자로 보고): 자원 수가 현행(데이터에 있는 기존 노선·장비 수)의 2배를 넘거나 적재율 < 30% 면 기준이 비현실적이다. 원인 후보: 비율 한도를 짧은 구간에 그대로 적용(→ 비율 또는 +분 중 큰 값), 선택 규칙이 멀리서 거점 근처로 건너뜀(→ 최근접 우선), 후보가 너무 잘게 쪼개짐(→ 소규모 통합).
5. 비교 실험 10분: 선택 규칙 3~5개 × 핵심 지표 표 → 사용자가 고른다. 스크립트를 `tools/experiment_*.py` 로 남긴다.
6. 결정성: 같은 입력 → 같은 출력 (정렬 키에 ID 포함, random 금지 또는 seed 고정).

## 보고
