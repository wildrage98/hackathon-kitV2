# 확인 문제 대비 — "제출 전 이해도 확인"

## 실제 형식 (2026-10-31 2차 예선에서 확인)
- 제출 절차 안에서 **6문항 × 5분**, 문항마다 타이머, 시간이 끝나면 현재 답이 자동 확정. 이전 문제로 못 돌아감.
- **복사·붙여넣기 불가.** "답변은 평가에 반영".
- 질문은 LLM 이 **내 제출물에서 생성**한다: HOW_TO_RUN 의 문장("약 2분", "작업 등록과 별도 worker", "직행을 먼저 확보한 뒤 병합"), AI_COLLABORATION 의 정책 이름("조건부 도보 정책")을 그대로 인용했다.
- 안내문에서 확인할 것: 이 30분이 3시간 **안에** 포함되는지 → 포함이면 제출 시작을 종료 −40분으로.

## 질문을 유도하는 법 = 문서에 답을 먼저 심는다
1. 굵은 소제목 6개(scaffold 의 HOW_TO_RUN 양식)를 **전부** 채운다. 생성기는 "결정처럼 보이는 문장"을 고르므로, 결정·대안·제약·숫자가 있는 문장을 내가 골라 둔다.
2. 방어 못 할 문장은 쓰지 않는다. 시간을 썼으면 로그가 있어야 하고, AI 가 만든 구조(큐·worker)를 내가 설명 못 하면 질문은 반드시 거기로 온다 → 설명 못 할 구조는 제출 전에 단순화한다.
3. AI_COLLABORATION 은 ⑥의 원문이다. 정책에 이름을 붙이고, 수용/수정/폐기 각 1개 이상 + 전후 숫자 + 테스트명.
4. 제출 15분 전 리허설: `python3 tools/quiz_prep.py --project <이름>` → 에이전트 `prompts/09-quiz.md`(`$quiz-prep`) → `docs/QUIZ.md` 읽고 `[근거 없음]` 고침 → 암기 카드(파일 5·테스트 5·숫자 5·명령 3·한계 3) 두 번.

## 답 틀 (5분 = 읽기 30초 + 뼈대 30초 + 타이핑 3분 + 검토 30초, 500자)
```
[결론 1문장]   "~는 ~방식으로 했고, 대안 ~는 ~때문에 버렸다."
[근거]         파일 경로 · 테스트명 · 숫자 · 명령 결과
[대안/비교]    버린 대안과 이유, 또는 정상 경로와의 차이
[제약/한계]    감수한 것, 검증 못 한 것 + 검증하려면 X
```
- 첫 문장이 결론. 모든 문단에 식별자나 숫자 1개 이상 ("plancheck.py 의 over_capacity", "5,883개 노선 위반 0").
- "모르겠다" X → "검증하지 못했다. 검증하려면 X".
- 약점은 내가 먼저. 마지막 한 줄은 한계 또는 개선안.
- 묻지 않은 걸 길게 쓰지 않는다. 500자 넘기면 타이핑이 안 끝난다.
