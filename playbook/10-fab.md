# 10. 제조 현장(팹) 운영 과제 — 유형별 데이터 · 규칙 · 지표 · 질문

현장 운영 과제는 공정 물리가 아니라 **운영 문제 + CSV + 규칙 문장**으로 온다. 뼈대는 I 형(09-service)과 같다:
CSV 검증·적용 → 규칙 검증기(verify) → 가장 단순한 판정/배정(run) → 지표 → 역할별 화면 → 내보내기. 바뀌는 것은 `engine.run/verify` 와 담당자 질문.

| 로트 / 웨이퍼 / FOUP | 함께 흐르는 웨이퍼 묶음(보통 25매) / 낱장 / 로트를 담는 운반 용기 |
| FDC / 트레이스 / 요약값 | 설비 센서 이상 감지 / 초 단위 원시 시계열 / 런·스텝별 평균·최대 등 |

| MES / 디스패칭 / WIP / Hot lot | 생산 실행 시스템 / 어느 로트를 어느 설비에 먼저 / 재공 / 최우선 로트 |

| Q-time | 두 스텝 사이 허용 대기 시간(넘으면 재작업·폐기) |

## A. 설비 이상 탐지 · 알람 운영 (FDC)
- 데이터: equipment(설비·챔버·종류) · recipes · sensor_log(설비×시각×센서) · equipment_state(상태 구간) · alarm_history · engineers(담당·교대)
- 규칙 문장 예: 상태가 RUN 일 때만 판정 / 레시피별 기준 / 연속 N회 초과 시 알람 / M회 연속 정상이면 해제 / 등급 승격 / 같은 설비 같은 원인은 한 알람 / PM 구간 데이터 제외 / 담당자 배정
- 지표: 알람 수(등급별) · 심은 이상 대비 탐지율·오탐율 · 탐지 지연 · 설비별 알람 상위
- 질문: 기준값 출처(스펙/과거 분포) · 기준과 같을 때 포함? · 지속 조건 N · 해제 조건 · 상태 전환 직후 몇 초 제외? · 결측·끊김은 알람? · 오탐과 미탐 중 무엇이 더 비싼가 · 알람이 너무 많다는 기준(하루 몇 건)
- 모듈: timeparse · quality · rules(when=상태, min_consecutive) · stats_detect · alerts · spc · evalmetrics · svgchart
- 관점: 고정 기준 대신 **같은 레시피를 도는 동료 설비 대비 편차**(장비 간 매칭) — 기준이 없을 때의 제안으로 좋다
- 함정: 상태 전환 순간 오탐 / 타임존·형식 혼합 / 센서 단위 불일치 / 끊김 후 복귀 시 연속 카운트

## B. 로트 디스패칭 (설비 투입 순서)
- 데이터: lots(우선순위·납기·현재 스텝·수량) · equipment(가능 레시피·상태·용량) · process_time(레시피×설비) · setup/전환 시간 · pm_schedule · qtime
- 규칙: 자격 설비만 / PM·DOWN 구간 투입 금지 / 한 설비 동시 1로트(또는 배치 용량) / Hot lot 우선 / 전환 시간 반영 / Q-time 초과 금지 / 시작 ≥ 도착
- 지표: 납기 지연 로트 수·총 지연 · 평균 대기 · 가동률 · 전환 횟수 · Q-time 위반 0
- 질문: 우선순위 정의(Hot > 납기 > 선입?) · 지연과 가동률 중 무엇이 우선 · 전환 시간은 고정인가 쌍별인가 · 계획 기간 · 진행 중 로트는 고정인가
- 모듈: schedule(dispatch·compare_rules·metrics) · verify · report
- 함정: 작업 중 로트 선점 / 자정 넘김 / 같은 로트의 다음 스텝 선후 관계

## C. 반송 배정 (OHT · FOUP)
- 데이터: transport_requests(출발·도착·요청 시각·기한) · vehicles(위치·상태) · nodes/bays · travel_times(비대칭 가능) · stockers(용량)
- 규칙: 차량당 동시 1 FOUP / 가장 이른 가용 시각 ≥ 요청 시각 / 기한 내 도착 / 스토커 용량 / 차량 상태(충전·정비) 제외
- 지표: 평균·최대 대기 · 기한 초과 수 · 공차 주행 비율 · 차량 가동률
- 질문: 기한은 상한인가 목표인가 · Hot lot 반송 우선 · 구간 혼잡·교행 제약을 볼 것인가(보통 범위 밖으로 합의) · 초기 위치
- 모듈: vrp(make_routes·timetable 패턴) · geo(좌표 있으면) · schedule · verify
- 함정: 왕복 소요시간 비대칭 / 빈 차 이동 시간 누락 / 같은 시각 요청의 결정성(정렬 키에 ID)

## D. 예방 정비(PM) · 정비 인력 배정
- 데이터: equipment(PM 주기·마지막 PM·라인·소요) · engineers(자격·교대) · work_schedule(근무·휴무) · line_limits(동시 다운 한도) · parts(선택)
- 규칙: 주기 초과 금지(기한 = 마지막 PM + 주기) / 자격 보유자만 / 근무 시간 안 / 휴무자 제외 / 같은 라인 동시 다운 ≤ k / 1인 동시 1작업 / 필요 인원 충족
- 지표: 기한 초과 0 · 라인별 최대 동시 다운 · 인력 부하 편차 · 생산 손실 시간
- 질문: 주기는 달력인가 가동 시간인가 · 앞당김 허용 폭 · 야간 PM 가능? · 동시 다운 한도 출처 · 근무표와 기본 교대가 다르면 무엇이 우선
- 모듈: schedule · verify · csvschema · dbcore
- 함정: 자정 넘는 교대의 기준일 / 휴무 변경본 적용 후 재생성(stale) / 자격 만료일

## E. 계측 샘플링 선택 · 가상 계측
- 데이터: lots/wafers · process_history(설비·챔버) · metrology(일부만 측정) · sensor_summary · 계측 설비 용량
- 규칙: 계측 용량 ≤ 일일 한도 / 설비·챔버마다 최소 n매 / PM 직후 첫 로트는 필수 계측 / 연속 미계측 로트 ≤ m
- 지표: 계측률 · 미계측 구간 최대 길이 · 예측 오차(MAE) · 놓친 이상 수
- 질문: 리스크 정의(무엇을 놓치면 안 되나) · 필수 계측 조건 · 예측값을 판정에 써도 되는가
- 모듈: stats_detect · groupstats · evalmetrics · rules
- 함정: 측정된 것만으로 오차를 재면 낙관적 / 시간 순서 누설(미래 데이터로 과거 예측)

## F. 수율 · 불량 원인 분석
- 데이터: lot_history(로트×스텝×설비·챔버·시각) · inspection(불량 bin·수량) · 설비 이벤트(PM·알람)
- 산출: 요인 순위(설비·챔버·레시피·시간대) + 근거(불량률·lift·표본 수·검정) + 재현 명령
- 질문: 불량 정의(어느 bin) · 기준 불량률 · 의심 기간 · 이미 아는 원인 제외 여부
- 모듈: groupstats(rate_by·rank_factors·chi_square·crosstab) · spc · report · svgchart
- 함정: 표본 적은 그룹의 높은 불량률 / 교란(특정 제품만 그 설비) / 다중 비교

## G. 정합성 (MES ↔ 설비 로그 ↔ 마스터)
- 데이터: 두 출처의 같은 사건(로트 트랙인·아웃) · 마스터
- 산출: 한쪽에만 있는 것 / 값 불일치 / 중복 / 시각 차 허용 폭
- 모듈: reconcile · csvschema

## 공통 — 담당자에게 항상 묻는 것
1. 기준 숫자의 출처와 경계(같을 때 포함?) — 상한인가 참고치인가
2. 무엇이 더 비싼가(오탐/미탐, 지연/유휴, 다운/과정비)
3. 지금은 어떻게 하고 있고 가장 큰 불편은 무엇인가, 최근 사례 1개
4. 범위 밖으로 둘 것(실설비 연결, 실시간, 혼잡·교행, 비용)
5. 날짜·교대의 기준일(자정 넘김), 근무표와 기본값이 다를 때 우선순위
