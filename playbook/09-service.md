# I. 서비스형 — 웹 + DB + 배치 계산(배정·노선·일정) + 배포 요건

## 단서
"웹 서비스를 개발", 요구사항 번호 5개 이상, 역할 2개(운영자/사용자), 데이터셋 선택·검증·적용, 재계산, 내보내기(JSON 스키마), DB 영속, 헬스체크, `.env.example`, `Dockerfile`, 실행 안내 문서 양식, 담당자 DM.

## 0분에 할 일
1. `bash tools/new_webapp.sh <이름> --data <CSV폴더>` → 바로 실행해 로그인·데이터셋·헬스체크가 뜨는 것 확인 (5분)
2. 요구사항 번호마다 한 줄 → `docs/REQUIREMENTS.md` (상태 열: 화면 / API / 테스트 / 문서). "해야 합니다" 문장도 전부 행으로.
3. 루트 README 는 수정 금지 (setup.sh 가 해시를 저장, preflight 가 확인). 실행 안내는 과제가 지정한 파일명·양식으로.

## 질문 (메신저, 묶음)
- 운영: 결과를 누가 언제 보나 / 지금은 어떻게 하나(엑셀·PDF·전화) / 가장 자주 오는 문의 / 최근 실제 사례
- 날짜·시간: 자정 넘김 근무의 기준일 / 기본 근무조와 날짜별 근무표가 다르면 무엇이 우선 / 휴무·예외 처리
- 편의 기준(숫자): 걸어서 몇 분부터 멀다고 하나 / 몇 분 넘으면 이탈 / 직행 대비 몇 배부터 불만 / 상한인가 참고치인가
- 효율 기준: 차량(자원) 수 최소가 우선인가, 이용 시간 최소가 우선인가 / 현행 대비 얼마나 줄어야 의미 있나
- 데이터: 기록 집계 기준일 / 실적과 계획의 차이 해석 / 특정 날짜 이상치(휴무 급증 등)의 배경
- 없다고 하면: "X로 가정하고 화면에서 바꿀 수 있게 두겠습니다" → 확정 → AGREEMENT

## 순서 (180분 기준)
```
0-15    scaffold 실행 확인 → README → REQUIREMENTS.md → 질문 묶음 1
15-30   데이터 프로파일 → specs.py(열 규칙·참조) → 데이터셋 검증 화면 동작 → 질문 묶음 2 → AGREEMENT
30-60   규칙 검증기(verify) 먼저 → 최소 계산(가장 단순한 greedy, 규칙만 지킴) → run → 화면에 숫자
60-100  계산 품질(기준 반영, 지표) → 운영 조건 재계산 → 사용자 화면
100     체크포인트: REQUIREMENTS 상태 열 전부 채워졌나 → 없는 것부터
100-130 내보내기(스키마) → 변형 데이터셋(정상 1·오류 3) → stale 동작 → 테스트
130-155 Dockerfile·.env.example·헬스체크 확인 → HOW_TO_RUN(양식 그대로) → AI_COLLABORATION
155-170 preflight submit → prompts/06·07 → DECISIONS 통독
```

## 최소 실행본 (30분)
scaffold + specs.py + engine.run 이 "규칙을 지키는 아무 답" 하나를 내고 verify 가 통과 → 화면에 지표 1개. 최적화는 그 다음.

## 계산(배정·노선·일정) 패턴
- 지점→후보 배정: `kitlib.vrp.cover_assign` (도보 한도 2단계 + 예외 + 소규모 통합)
- 묶음·순서·시간표: `kitlib.vrp.make_routes` + `timetable` (정원·우회 한도·거점 방향)
- 기준은 **우선순위 목록**으로 적고(규칙 > 접근 > 우회 > 자원 수 > 시간) 숫자는 PARAMS 로 노출 → 바꿨을 때 지표 변화를 표로
- 첫 결과 숫자를 현행과 비교: 자원 수가 현행의 2배를 넘으면 기준(우회 배수·도보 한도·최소 인원)을 의심. 비교 실험 스크립트(변형 3~5개 × 지표) 10분

## 검증
- `engine.verify` 를 생성 코드와 **별도로** 작성 (규칙마다 코드 1개) → 일부러 깨뜨린 결과가 잡히는지 `kitlib.verify.mutate_check`
- 경계값: 정원과 같을 때 / 기한과 같을 때 / 자정 넘김 / 휴무자 / 한 지점 수요 > 정원 / 소요시간 비대칭
- 데이터셋: 정상 변경본(근무표 바꿈) 적용 → 재생성 → 숫자 달라짐 / 오류본 3종 → 거부 + 기존 유지 + 원인 행·열
- API: 401/403, 재시작 후 결과 유지, stale 409

## 함정
- 셀 오류 행을 버리면 참조 오류가 수백 건 연쇄 → 키가 살아 있으면 행 유지(`csvschema` 기본)
- "직행 대비 1.5배"를 짧은 구간에 그대로 쓰면 합승 불가 → 배수 또는 +분 중 큰 값
- 가장 가까운 "경로 이탈 최소" 선택은 멀리서 거점 근처로 건너뜀 → 최근접 우선(`make_routes` 기본)
- 적용 후 재생성 전 결과를 새 데이터 결과처럼 보여주기 → stale 표시 + 사용자 409
- 내보내기에 파일 저장창 → 서버 폴더 저장 + 화면 표시
- Docker 빌드에 pip → 네트워크 없으면 실패 → stdlib
- 실행 안내 문서를 README 에 씀 → 과제 지정 파일로
- 기준 숫자를 코드에 박음 → PARAMS/환경변수 + 문서에 "누가 정한 값"
